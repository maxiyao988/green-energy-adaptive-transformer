This protocol is immutable after creation. Existing repository code, data, caches, checkpoints, results and manuscripts are read-only. ## 1. Scope

Exactly the Step16 head-frozen primary: inputs O (original frozen V2) and C (Stage3a causal window-relative); S1 Fixed-trained and S2 Adaptive-trained backbones; each aggregator seed uses the backbone of the SAME seed; seeds {0,1,21,42,3407}; h={5,10,20}; Daily+Weekly; W3 TRAIN/VALIDATION/TEST partitions (30,634/6,290/6,647 rows,17 stocks,391 TEST dates). The Step15 S1 head-retrained sensitivity setting is excluded. Four aggregation variants: Fixed equal-weight reference (untrained), Static, Adaptive, constant-input gate. 60 backbones,240 final evaluation cells; no seed or specification selection.

## 2. Frozen-module evidence and caching

Read-only evidence: frozen_worker_v3.py:76 sets the original backbone to eval during expert caching; :116–143 configures the variants, freezes all parameters except aggregation, overrides train() to hold input projections, positional encoding, all eight experts and the head in eval; :165–167 asserts this during forward calls. Frozen training thus had dropout disabled in the frozen modules. Reuse these exact model factories, aggregation implementations, head and configure_variant by import; do not reimplement any model.

Reuse the existing immutable Step15 expert caches after verifying every backbone/cache SHA-256 and array contract, avoiding redundant disk copies. A new per-backbone cache manifest binds the float32 (N,8,32) arrays for TRAIN,VALIDATION,TEST, the frozen head/backbone state and the TRAIN-only (8,32) mean. Cache the complete aggregation input graph: four (N,32) expert outputs per branch; Adaptive router input is the ordered (N,128) concatenation, represented by the exact reshape/view of the branch cache; constant gate uses the TRAIN-mean (128) branch vector expanded identically over samples. The trained aggregator computes its weighted branch representation, and the imported frozen fusion head consumes their ordered concatenation; this weight-dependent head input must remain differentiable and is reconstructed by the original forward, never replaced with a precomputed input from a different aggregator. Cache manifests record shapes, view definitions and hashes. No new full-data builder is used while training.

## 3. Read order and strict phase barriers — user clarification

(i) Cache/bind and validate TRAIN,VALIDATION,TEST tensors for all60 backbones, without evaluating forecast metrics.
(ii) Load Step16 trained aggregation states and replay every VALIDATION cell first; only after all VALIDATION replays pass, replay every TEST cell. Compare predictions ONLY with the saved Step16 frozen predictions, requiring maximum absolute difference <=1e-6 for each cell, including Fixed. Output ONLY PASS/FAIL and the maximum absolute prediction difference per cell (alongside identifying fields and timestamps). Do not compute or display MSE, Rank IC, DA or any other performance metric from either replay. Read TEST prediction columns without realized returns for replay; inference uses dummy targets. Replay is solely a go/stop gate and cannot alter the grid, selection rule or any other setting. A failure stops before any training.
(iii) Train ALL new aggregators with TRAIN/VALIDATION data only. Do not open, hash, load or infer TEST tensors/predictions/targets during this phase. Worker file-audit guards enforce the registered TEST-path exclusion. No call to the formal trainer's built-in TEST evaluation is permitted.
(iv) Once all252 training jobs are finished and all learning rates are selected, enter a single final TEST-evaluation phase; perform TEST inference once for each of the240 final cells and compute all requested metrics. Never infer or score TEST for the unselected tuning trials. Model selection is irrevocably locked before this phase. Evaluation processes start after the training pool exits.

Record start/end UTC and wall seconds for cache, VALIDATION replay, TEST replay, tuning, remaining-seed training, overall training start/end, and final TEST evaluation. The report contains the phase audit trail. Pretraining replay and new-model final evaluation are distinct, explicitly authorized uses of TEST.

## 4. Training, initialization and tuning

CPU only. Each of exactly three parallel numerical workers sets, before importing torch, OMP_NUM_THREADS unset, MKL_NUM_THREADS/OpenBLAS/VECLIB/NUMEXPR thread overrides unset, OMP_DYNAMIC=FALSE, MKL_DYNAMIC=FALSE; torch intra12/inter12. Log actual counts/environment, load averages, start/end time and per-job runtime; keep caffeinate -i active through the queue. Workers refill as jobs finish. No other training queue is started.

Identical across Static, Adaptive and constant-input gate: formal Adam (unchanged defaults), batch32, raw log-return target, Huber delta1, formal gradient clip1, same seeded model initialization as Step15 (Static zero logits; Adaptive and constant gate identically initialized routers for a given seed), independent TRAIN DataLoader generator42, shuffle TRAIN only; VALIDATION batch32 deterministic order. Frozen parameters remain identical and eval throughout. Reuse the unchanged main_v2 train_one_cell training-prefix AST (through best-state restoration, before its TEST-evaluation statements) in an isolated namespace, binding only cached TRAIN/VALIDATION loaders and the imported frozen model configuration. The source training statements are preserved, archived and hashed; removing the TEST suffix implements the required separation without reimplementing the loop or models.

Changes: learning rates {1e-4,1e-3,1e-2}; maximum50 epochs; early stopping patience10 on VALIDATION Huber loss, same formal >1e-12 improvement rule; checkpoint is restored best VALIDATION-loss state. No training for Fixed.

Tune on seed0 ONLY: for each aggregator (Static,Adaptive,constant gate) × input × backbone × horizon, fit all three rates from the same seeded initialization with the same generator42. Compute VALIDATION MSE of each restored best-Huber checkpoint; select the minimum, exact ties go to the smaller learning rate. Do not choose an epoch by validation MSE. There are36 tuning groups,108 trial fits. Record every trial's validation MSE, curve, best epoch, stopping epoch, state and failure status. Then fit seeds1,21,42,3407 at the selected learning rate for that group (144 fits), reusing the selected seed0 checkpoint; do not retrain seed0. 252 total fits; no TEST-based tuning.

Report every rate and cell, including divergent or degenerate outcomes. Nonfinite losses/gradients trigger the original formal failure guard for that run. Retain its partial history, failure reason and best finite validation checkpoint if one was reached; a divergent tuning trial is ineligible for LR selection (validation selection score +infinity), solely on TRAIN/VALIDATION evidence. If every rate in a group fails, stop and ask rather than substituting a rate. A failed remaining-seed fit remains an explicitly failed final cell with unavailable metrics; do not silently drop it to compute an apparently complete five-seed summary. Constant outputs or undefined Rank IC remain reported, with missingness recorded; never change the rate or rerun a seed based on TEST.
