# Pre-registered Step22B protocol

Status at registration: code delivery only. No Step22B training, reproducibility replay, timing pilot, TEST inference or hypothesis test has been run. This protocol is immutable after its SHA-256 is recorded in RNG_MANIFEST.json.

## 1. Question and reporting commitment

H1: no Static − Adaptive difference favoring Adaptive. H2: LSTM matches or outperforms Adaptive. For each alternative setting separately, a conclusion meets the robustness criterion if no relevant horizon has an Adaptive-favoring MSE or Rank IC contrast with Holm-adjusted p < 0.05. Report all outcomes regardless of direction. DA is reported and tested, but is not part of the H1/H2 criterion. No configuration, rate, seed or cell is selected by TEST outcomes.

Contrasts are always first minus second. For Static − Adaptive, positive MSE differences and negative Rank IC differences favor Adaptive. For Adaptive − LSTM, negative MSE differences and positive Rank IC differences favor Adaptive. Undefined required tests or missing/failed cells make the relevant verdict INDETERMINATE; they never establish robustness. The verdict is NOT MET if at least one defined required contrast significantly favors Adaptive, even if another contrast is undefined; otherwise MET requires all six relevant tests (two metrics × three horizons) to be defined and none to favor Adaptive significantly.

## 2. Settings and unchanged formal protocols

T0: learning rate 1e-4, Huber delta 1; reuse Step16 runs, without retraining, except the explicitly required reproducibility gate. T1: learning rate 3e-5, Huber delta 1. T2: learning rate 1e-4, Huber delta sigma_h, with sigma_5=0.098083, sigma_10=0.138578, sigma_20=0.195560. These constants are fixed; no estimation or tuning occurs.

Everything else follows the Step16 source paths: CPU, original model classes and factories, original dropout, Adam, batch size 32, gradient clipping 1.0, maximum 100 epochs, patience 10, initialization, per-ticker/frequency/channel TRAIN-only normalization, and each trainer's checkpoint improvement rule. Early stopping and restoration use validation **training loss** for that setting, never validation MSE. Formal Pathformer improvement thresholds (including 1e-12 where present) and the LSTM strict minimum rule are retained verbatim.

Static seed42 uses Experiment3; Adaptive seed42 uses main_v2.train_one_cell; other Static/Adaptive seeds use Experiment4.train_and_validate_cell. Optional Fixed uses Experiment3 with the run seed for initialization and generator42 for the shuffled loader. Pathformer shuffled DataLoaders use independent generator42 for every seed; LSTM uses its original global-RNG loader, initialized with the run seed, with no explicit DataLoader generator. LSTM uses the same formal entrypoint and CPU backend override as B5. No model or training loop is reimplemented: source functions are imported; their training-only AST prefixes are compiled unchanged, ending after restoration and before TEST inference or original-path writes. Process-local bindings supply the data, seed, learning rate and loss delta. The one literal LSTM Huber delta is overridden through a criterion factory; the loop is unchanged.

## 3. Scope, schedule and timing gate

C (window-relative), Daily+Weekly, W3, Static/Adaptive/LSTM, horizons 5/10/20, seeds {0,1,21,42,3407}. T1 and T2 each have 45 core fits, 90 total. Optional Fixed adds 30 fits. The head-retrained/frozen-aggregator experiments are out of scope: these are full end-to-end models with their usual training dropout.

One isolated T0 reproducibility fit runs first. If it passes, the first three grid runs are T1, h20, seed0, one each of Static, Adaptive, LSTM. They run concurrently and are reused as their grid cells; there are no extra timing-only retrainings. After these three finish, D is the actual UTC elapsed seconds from launch of the first pilot worker to completion of the last pilot worker, including process startup, outputs, load and sleep. Estimated core wall time is D × (90/3); estimated core+Fixed time is D × (120/3). The gate-fit time is separately reported, excluded from these grid projections. UTC elapsed time and monotonic time are stored separately because macOS sleep can affect them differently. A failed pilot makes the timing gate undefined and stops the grid with a report.

If core projection >14h: STOP and report, without TEST reads. Otherwise include all 30 Fixed fits if and only if core+Fixed projection <=12h; otherwise exclude Fixed solely by timing. No result-dependent choice is allowed. Following the pilot, order is setting T1 then T2; seed 0,1,21,42,3407; horizon20,10,5; Static,Adaptive,LSTM,(Fixed if allowed), skipping the already completed pilot cells.

Exactly three training worker slots, refilled as jobs finish; the last tail may contain fewer than three and the reproducibility gate necessarily uses one. Each fit is a fresh process, CPU intra12/inter12, OMP_NUM_THREADS unset, OMP_DYNAMIC=FALSE, MKL_DYNAMIC=FALSE, configured before Torch import (environment) and immediately after Torch import (Torch settings). Other explicit numerical-library thread counts are unset as in the 12/12 sources. No other experiment is launched by this runner. A caffeinate -i child accompanies the queue. Resident applications are not closed. Log UTC start/end, actual elapsed seconds, monotonic seconds, epochs/best epoch, profile, environment, load averages and top CPU processes at start/every five minutes/end. Background load is timing context only; it is not a numerical explanation unless thread counts change.

## 4. Reproducibility gate

Retrain C Static h5 seed0 T0 using its Experiment4 path. Compare each epoch's validation loss with the Step16-source history; epoch sequence and length must match. Compare restored-best VALIDATION predictions and exact ticker/date keys and labels with the stored source VALIDATION predictions. Pass only if both maxima are <=1e-6. Report the per-epoch comparison and prediction maximum; no TEST reads. If failed or artifacts unavailable, STOP and report. The gate fit is diagnostic only; all T0 reported cells still come from Step16.

## 5. Read order and source protection

Only sample keys/split metadata, source code and manifests may be inspected before training. TRAIN/VAL arrays are selected by row from read-only NPY mappings; no TEST feature/label values, TEST predictions, saved TEST metrics, or bootstrap outcome files are accessed. The imported causal binding's raw tensor files, existing normalizer and loader builders are reused; removing TEST rows preserves TRAIN/VAL values and ordering. Compare normalized TRAIN/VAL values bitwise to the stored causal standardized tensors using the same row selection. Test-containing NPY files are mapped but only TRAIN/VAL-selected entries are accessed; do not scan or hash their entire contents before the barrier. Source manifest hashes may be recorded without reading those arrays. Original TEST paths and Step16 canonical/metric files are denied by an audit hook in training processes. Original-path writes are denied. No existing file may be modified or overwritten, including on restart. Runtime journals are immutable event files and numbered status.csv snapshots, not overwritten files.

After the gate and timing decision, every planned training job must have a verified terminal record (COMPLETE or FAILED, including degenerate runs). Only then create ALL_TRAINING_FINISHED.json containing the protocol hash, expected cells and artifact fingerprints. TEST workers validate this barrier and all training records before opening any TEST data. Existing T0 TEST predictions and new-model TEST inference are then evaluated in one final phase. No new training is permitted after the barrier. Full source-input hashes and unchanged-source checks are completed after this barrier. Restarts verify completed artifacts; no completed cell is retrained. Interrupted partial attempts are retained and retried in new exclusive attempt directories; recorded failures are retained and reported, not silently retried or selected away.

## 6. Evaluation and tests

For every model × setting × horizon report five-seed mean ± sample SD (ddof1) of TEST MSE, mean per-date cross-sectional Rank IC, and DA; also out-of-sample R² against the same-horizon W3 Global Train-Mean (raw TRAIN labels, float64 mean). DA excludes realized returns exactly zero; a zero prediction against a nonzero realized return is incorrect. All predictions, labels, squared losses, setting-specific Huber losses, DA correctness/validity and routing weights are saved as per-seed stock/date CSVs; date and stock summaries are saved too. Undefined Rank IC stays undefined. Five-seed summaries do not silently average fewer than five finite seeds.

For T1 and T2: joint paired seed×date bootstrap for Static−Adaptive and Adaptive−LSTM, plus Fixed−Static if Fixed is included. Metrics MSE, Rank IC and DA; B=20,000, L=h, common noncircular moving date blocks, the Step16 paired-seed resampling and centered two-sided p-value. Import Step16 statistics16_v3 and its Step5/7/15 dependencies rather than implement a new test. Preserve contiguous seed×date arrays, all 391 calendar dates and paired-valid IC handling. Reuse and verify the stored Step16 resampling draws; bootstrap seed base20261019 with SeedSequence([20261019,h,h,1]). DA uses jointly resampled correct-count differences divided by resampled nonzero-return counts, preserving the Step21 definition. Report point estimate, 95% percentile interval, raw p, Holm p, and first-arm seed wins/losses/ties. Holm across the three horizons within contrast × metric × setting, independently. Undefined tests use p=1 only as a conservative multiplicity placeholder; raw p/interval remain N/A. Do not report additional tests or cross-setting tests.

## 7. Training behavior and reporting

Save all per-epoch train/validation Huber losses and validation MSE. Best-epoch distribution includes every seed and setting. Step19 change = 100 × (last_epoch_loss − best_epoch_loss)/best_epoch_loss, separately train/validation, then equal-weight mean over seeds; undefined denominators remain N/A. Mean learning curves average only observed seed histories at that epoch, with count reported. T2 curves are in its own Huber units, explicitly labeled.

For Static and Adaptive, branchwise TEST routing diagnostics: mean absolute deviation from0.25; mean of per-scale population SD over observations; between-date share = sum of sample variances of date-mean weights broadcast to observations / sum of sample variances of all observation weights (pandas ddof1). Numerical constants (max per-scale range <1e-7) have SD0 and share N/A; retain the range and denominator for audit. Report T0/T1/T2 side by side descriptively. Static logits are saved. Failed/degenerate fits retain histories, errors and any valid restored state; an unfit model is not evaluated as if valid. Missing predictions are N/A, with keys/labels preserved.

REPORT_STEP22B.md starts with BLOCKING and contains the protocol SHA, gates and timing, every fit including failures, all summary/test/router/learning tables and H1/H2 verdicts separately for T1/T2. Interrupted/gate-failed runs write new STOP_REPORT timestamp files without overwriting a final report. No manuscript conclusion is selected from alternative settings.

All new code and artifacts are exclusively created under revision_work/outputs/step22b/. The delivery includes a run command and read-only status command; the user launches the computation. The script never modifies a stored protocol, source file, existing output, checkpoint or result. Training seeds and all statistical RNG seeds are fixed above and in RNG_MANIFEST.json.
